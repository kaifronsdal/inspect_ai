## Inaccuracies fixed

1. **chain() banner-hiding** — `solver=chain(banner(), generate())` wrapped the InfoEvent in a collapsed `SUB-AGENT: BANNER` span, so the transcript showed only `SUB-AGENT: BANNER` / `SUB-AGENT: GENERATE` / `SCORE` with no readable description. → Replaced with a single `repro_solver()` that calls `emit_bug_banner(DESC)` then `await generate(state)`. Banner now renders as an expanded `INFO: BUG-REPRO` panel at the top.

2. **where_to_look: wrong keystrokes** — "type `category_scorer ` (with trailing space)" actually opens the *operator* dropdown (`==`, `!=`, `in`, `not in`, …), not the value dropdown, so the user never sees the bug. → "type `category_scorer == ` (with the `==` and trailing space)" — this is what surfaces the `undefined` value suggestion.

3. **where_to_look: nonexistent hover tooltip** — "hover the `category_scorer` token for its tooltip" — hovering the token shows nothing (`.cm-tooltip-hover` count = 0). The `categories: undefined undefined undefined` text lives in the autocomplete **info side-panel** (`.cm-completionInfo`) shown beside the highlighted dropdown item. → "clear the input and type just `category_scorer` → look at the info panel beside the highlighted dropdown item."

4. **observed: wrong count/quoting** — "Autocomplete suggests `== "undefined"`, `== "undefined"`, `== "undefined"` — one per category" — in reality CodeMirror dedups the three `undefined` values to a **single unquoted `undefined`** entry (because `valueToString(undefined)` → the string `undefined`, not `"undefined"`). → "The dropdown offers a single `undefined` as the only category-value suggestion (above the generic variable list)."

Also tightened: input is labeled **`FILTER:`** (top right of Samples tab), added "close this sample dialog → log-level Samples tab" so the path starts from where the banner is read, and noted the real values are visible in the score column for contrast. `expected` extended to cover the info-panel text too.
