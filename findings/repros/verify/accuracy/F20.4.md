# F20.4 — Description Accuracy

**Verdict (unchanged):** CONFIRMED
**Banner visible at Default:** no → fixed
**Inaccuracies found:** 2

## Inaccuracies fixed

1. **Banner hidden inside collapsed `SUB-AGENT: BANNER` span** (chain() problem) → replaced `solver=chain(banner(), generate())` with a single `repro_solver()` that calls `emit_bug_banner(DESC)` then `await generate(state)`. Banner now appears as the first `INFO: BUG-REPRO` panel in the Transcript under the Default filter, fully expanded.

2. **"the score pill in the header row above the tabs"** → **"the SCORE column in the sample header (top-right, above the tab bar)"** — there is no pill; the header is a labelled column grid (`ID | INPUT | TARGET | ANSWER | SCORE`) and the score renders as plain text under the `SCORE` label. Calling it a "pill" implies a styled badge, which is exactly what this finding says is *missing* here, so the wording was actively confusing.

## Improvements (not strictly inaccuracies)

- `where_to_look` rewritten to be actionable: now tells the user to open `should_be_C` → click **Scoring** tab, then names each of the three SCORE locations precisely (header top-right / Scoring-tab scorer grid / Samples list). All three labels verified against the DOM (`SCORE` column header in ag-grid list; `SCORE` label in sample header; `SCORER | ANSWER | SCORE | EXPLANATION` columns in Scoring grid).
- `observed` now states the badge colours explicitly (**green** for `C`, **red** for `I`) and notes that header + badge are visible side-by-side on the Scoring tab — matches DOM evidence (`_circle_ _green_` / `_circle_ _red_` spans vs plain-text header cell).
- `extra` now mentions that `should_be_X` renders plain `X` everywhere (falls through passFail), so the user isn't surprised when that sample doesn't show the divergence.
