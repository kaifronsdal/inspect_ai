# F20.14 — Description Accuracy

**Verdict (unchanged):** CONFIRMED
**Banner visible at Default:** no → **fixed** (was hidden inside collapsed `SUB-AGENT: BANNER`)
**Inaccuracies found:** 3

## Inaccuracies fixed

1. **`chain()` hid the banner.** `solver=chain(banner(), generate())` wrapped the
   `emit_bug_banner()` InfoEvent inside a collapsed `SUB-AGENT: BANNER` span, so
   the description was invisible at the Default filter. → Replaced with a single
   `repro_solver()` that calls `emit_bug_banner(DESC)` then `await generate(state)`.
   The `INFO: BUG-REPRO` panel is now the first expanded item in the transcript.

2. **"look at the … dict_scorer score column" — no such column exists.** The
   SCORERS picker only offers `list_scorer` plus the dict's individual keys
   (`zero` / `third` / `one`); there is no aggregate `dict_scorer` column. →
   `where_to_look` now points only at the **LIST_SCORER** column (with a hint to
   widen it, or read the **SCORE** header inside any sample dialog where the
   full `[0, 0.333, 1.0]` is always visible). The dict-scorer fact moved to
   `extra` as a code-level note.

3. **"Dict score … shows `0` unformatted next to `0.333` / `1.0`" — not
   observable.** Because the grid splits dict scores into per-key columns, the
   `ObjectScoreDescriptor` render path is never exercised on screen in this
   repro. → Removed the dict claim from `observed`; `extra` now states the
   identical `&&` guard exists in `ObjectScoreDescriptor.tsx` without claiming
   it is visible here.

## Verified-accurate claims (unchanged)

- LIST_SCORER cell text is exactly `[0, 0.333, 1.0]` (DOM `inner_text`, all 3 rows).
- Sample-dialog SCORE header also reads `[0, 0.333, 1.0]`.
- `0` lacks a decimal place while sibling `1` renders as `1.0` → asymmetry confirmed.
