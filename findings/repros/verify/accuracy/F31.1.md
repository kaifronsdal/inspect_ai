## Inaccuracies fixed

1. **chain() banner-hiding** — `solver=chain(banner(), generate())` wrapped the InfoEvent in a collapsed `SUB-AGENT: BANNER` span; the banner table was invisible under the Default filter. → Replaced with a single `repro_solver()` that calls `emit_bug_banner(DESC)` inline before `await generate(state)`. Banner now renders as an expanded `INFO: BUG-REPRO` panel at the top.

2. **`where_to_look`: "Task tab (sometimes labelled *Info*)"** → **"log-level Task tab (top row: Samples / Task / Models / Info / JSON)"** — Task and Info are two *separate* top-level tabs in this viewer; the parenthetical sent users to the wrong tab. Also added "Close this sample →" since the bug lives at the log level, not the sample level.

3. **`where_to_look`: "Scan every card on the page"** → **"The only card rendered is Task Info (Task ID, Run ID, Git Revision, Inspect, Start, End, Duration)"** — there is exactly one card; "every card" implied several. Naming it and its fields lets the reader confirm at a glance that no Config card exists.

4. **`extra`: "The header SecondaryBar shows a *merged* config … under the generic label 'Config'"** → **"The header bar above the tabs shows only DATASET / SCORER / DURATION for this log — no Config column (its source is `plan.config` + `task_args`, both empty here, *not* `EvalConfig`)"** — in this repro the SecondaryBar has **no** Config column at all (both sources empty). Old text told users to look for a label that isn't on screen. Also noted the implicit `1 x 7 samples` epochs leak.

5. **`expected`: "Open the JSON tab"** → **"Open the log-level JSON tab"** — disambiguates from the sample-level JSON tab.

6. **Added severity note** per verdict downgrade: `**Note:** impact is minor — data is still reachable via the JSON tab; recommend MEDIUM severity (was HIGH).`
