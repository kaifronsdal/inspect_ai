## Inaccuracies fixed

1. **`where_to_look` omitted the Debug filter** → added "**switch the filter to Debug** (top-right `Events: Default` button → `Debug`; sandbox events are hidden under Default)". Under the Default filter only `SOLVER:` + `INFO:` panels render — the `Sandbox: exec` event is excluded entirely, so a user following the old instructions would find nothing to look at.
2. **Panel name "Sandbox: Execute"** → **"Sandbox: exec"**. The title element's source text is `Sandbox: exec` (rendered uppercase as `SANDBOX: EXEC` via CSS). "Execute" does not appear anywhere on screen.
3. **"expand the … event"** → **"already open, no expand needed"**. The panel has no collapse chevron (`bi-chevron-right` / `bi-chevron-down` count = 0); it renders fully expanded with no expand affordance. Telling the user to "expand" it is misleading.
4. **Missing minor-impact note** → added `**Note:** impact is minor — this state is **synthetic-only**. The sole production emitter of SandboxEvent(action="exec") (util/_sandbox/events.py) always sets cmd to a joined string, so real sandbox calls never reach cmd=undefined.` per CONFIRMED_MINOR verdict. Also reframed the fix recommendation to reference sibling `ReadFileView`/`WriteFileView` which already use `!event.file`. Dropped the redundant "(Event constructed directly — no real sandbox needed.)" line, now subsumed by the impact note.

Also tightened `observed` from "an empty `<pre>`" → "nothing beneath it (two empty `<pre>` elements in the DOM)" to match what the user actually sees (a dangling **COMMAND** label, not a visible empty box) vs. what's in the DOM.
