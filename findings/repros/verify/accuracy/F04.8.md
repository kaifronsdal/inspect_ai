**Banner visible at Default:** no → fixed (was hidden inside collapsed `SUB-AGENT: BANNER`)
**Inaccuracies found:** 4

## Inaccuracies fixed

1. **Banner hidden by `chain()`** — `solver=chain(banner(), generate())` wrapped the InfoEvent in a collapsed `SUB-AGENT: BANNER` span and the model call in `SUB-AGENT: GENERATE`. → Replaced with a single `repro_solver()` that calls `emit_bug_banner(DESC)` then `await generate(state)`. Banner now renders as an expanded `INFO: BUG-REPRO` panel at the top of the Transcript under the Default filter, and the Model Call is a top-level event.
2. **`where_to_look`: "click the **Usage** tab"** → **"click the **All** sub-tab → look at the **Usage** section"**. The Model Call panel's sub-tabs are `SUMMARY | ALL | API`; there is no Usage tab. Usage is a labelled section inside the All sub-tab.
3. **`where_to_look`: "top-level **Models** / **Usage** tabs in the log header"** → **"log-level **Models** tab → **Model Usage** card at the bottom"**. There is no log-level Usage tab; the ModelUsagePanel renders as a "Model Usage" card at the bottom of the Models tab.
4. **`observed`: "**cache_write** row: blank. **Reasoning** row: blank."** → **"The **cache_write** and **Reasoning** rows are omitted entirely — separate truthy guards drop the whole row when the value is `0`."** DOM dump shows only four rows (`INPUT` blank, `CACHE_READ 100`, `OUTPUT 50`, `TOTAL 150`); cache_write and Reasoning are guarded by `if (usage.input_tokens_cache_write)` / `if (usage.reasoning_tokens)` and never reach the value-render path that F04.8 targets. Also tightened `expected` to focus on the `input` row (the one case that actually exercises `row.value ? … : ""`).
