# F40.5 — `web_search` renderer output never displays (array fails `isValidElement`)

**Prior verdict:** INCONCLUSIVE
**New verdict:** CONFIRMED_MINOR
**Batch:** 40-content | **Port:** 7650 | **Log:** `2026-04-24T01-25-18-00-00_F40.5-web-search-array-fallthrough_XH9jjouQcTagcx2aWDDUkt.eval`

## What the finding claims

`packages/inspect-components/src/content/RenderedContent.tsx:73,260-281` — the `web_search` content renderer returns `{ rendered: ReactNode[] }`; the dispatcher then tests `isValidElement(rendered)` (false for arrays) and falls through to `<span>{JSON.stringify(entry.value)}</span>`. Impact claimed: "Web-search tool results render as a raw JSON blob instead of the intended formatted query + links."

## What the repro's bug_description says to look for

> **Where:** Transcript tab → expand the **Sample Init** event → its **Metadata** sub-tab → row whose key is `web_search`.
> **Observed:** The `web_search` row's value is a single `<span>` containing the raw `JSON.stringify(...)` of the record (one long line starting with `{"query":...}`).
> **Expected:** A formatted block: search-icon + query text, followed by two clickable URL links each with its summary.

## Analysis

**The prior INCONCLUSIVE was a navigation failure, not a reachability problem.** The check script (`checks/F40_5.py`) never switched the transcript event filter to **Debug** (so `sample_init` stayed hidden) and never expanded the wrapping `Init` span. Once you do both, the `Sample` panel (= `SampleInitEventView`) appears with a `Metadata` sub-tab, and the bug is plainly visible.

**Reachability of the `web_search` renderer.** Of the seven `RenderedContent` call sites, five hard-code `entry.name` (`"Output"`, `"Explanation"`, `"sandbox_output"`, `"error"`, `"other-score-value"`) and `RecordTree` reduces object values to the *string* `"Object(N)"` before passing them through (so `typeof === "object"` fails). That leaves **`MetaDataGrid` (MetaDataGrid.tsx:72)** as the sole live path: it passes `{name: <key>, value: <value>}` straight from its `entries` record. Any `MetaDataGrid` consumer whose entries can contain a key literally named `web_search` with an object value reaches the renderer:

- `SampleInitEventView.tsx:101` → `entries={event.sample.metadata}` ← **the path the repro hits**
- `LoggerEventView.tsx:36` → parsed-JSON log message
- `SubtaskEventView.tsx:106` → subtask input/result
- and recursively, any nested object inside those (`renderObject` re-enters `MetaDataGrid`).

**Source confirms the defect.** `web_search` is at `Buckets.intermediate` and inserted before the generic `Object` renderer, so `.find()` picks it first; it returns an array (line 281); `isValidElement(array) === false` (line 73); fallthrough emits `<span>{JSON.stringify(...)}</span>` (line 90). Ironically the broken renderer makes things *worse* than its absence — without it the generic `Object` renderer would have shown a nested key/value grid.

**Why MINOR, not the finding's MEDIUM.** The finding's impact statement ("Web-search tool results render as a raw JSON blob") is overstated. Real `web_search` server-tool results are `ContentToolUse` blocks rendered by `ServerToolCall.tsx:84-101`, which has its own (working) `<a>`-link rendering and never enters `RenderedContent` with `name:"web_search"`. The `RenderedContent` `web_search` renderer is effectively orphaned legacy code; triggering it requires a metadata/subtask/log-JSON key *literally named* `web_search` shaped `{query, results:[{url,summary}]}` — vanishingly unlikely in real evals. The defect is real and reproducible, but the user-facing impact is near-zero.

## Recommended action

**Downgrade severity MEDIUM → LOW.** Keep the finding (the `isValidElement` guard is genuinely wrong and the same fragility could bite a future array-returning renderer). Fix is trivial: wrap in `<Fragment>` at line 281, or relax line 73 to `rendered !== undefined`. The repro is fine as-is; only the *check script* needs updating to (a) call `show_all_events()`, (b) click the `Init` span header, then (c) click the `Sample` panel's `Metadata` sub-tab.
