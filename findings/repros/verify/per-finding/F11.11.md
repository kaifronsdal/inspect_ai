# F11.11 — ApprovalEventView drops `approver`, `modified`, `message`

**Prior verdict:** CONFIRMED
**New verdict:** CONFIRMED
**Batch:** 11-tools | **Port:** 7633 | **Log:** `2026-04-23T04-58-04-00-00_F11.11-approval-event-drops-fields_4T6H4PjaWvDENd3XkkJQMa.eval`

## What the finding claims

`ApprovalEventView.tsx:22-31` renders only `decision` + `explanation` from the `ApprovalEvent`. The fields `approver: string`, `message: string`, and `modified?: ToolCall` (all present in the schema, `generated.ts:372-407`) are never read — so when `decision === "modify"`, the reviewer cannot see *who* approved or *what* the call was changed to.

## What the repro's bug_description says to look for

> **Observed:** Only `decision: modify` and the explanation are shown. The approver name (`F11.11_APPROVER_NAME_security_reviewer`), the modified tool call (`path=F11.11_MODIFIED_ARG_VALUE_sanitised_path`), and the model message (`F11.11_ASSISTANT_MESSAGE…`) are all missing.
>
> **Expected:** Approval card shows WHO approved, the original→modified argument diff, and the assistant message that accompanied the call.

## What I actually observed

## Analysis

Source, screenshot, DOM, and JSON all line up:

- **Source** (`ApprovalEventView.tsx:22-31`): the JSX reads only `event.decision` (→ `decisionLabel`/`decisionIcon`) and `event.explanation`. `event.approver`, `event.modified`, `event.message`, and `event.call` are never referenced.
- **Rendered DOM**: the EventRow `.card` contains exactly `<icon> + "Modified" + <explanation>`. No other elements.
- **JSON tab**: `approver`, `modified`, `message` are all populated with the repro's sentinel values, proving the data made it into the log.

A reasonable user reviewing an approval audit trail would expect to see who the approver was and — especially for `decision: "modify"` — what the call was rewritten to. The adjacent Tool panel makes the gap concrete: it shows the *pre*-modification arguments alongside *post*-modification output, and the Approval row gives no diff to reconcile them. The `message` field is the weakest of the three (the same assistant text is visible inside the preceding Model Call panel), but `approver` and `modified` have no surrogate anywhere in the transcript UI.

Prior verdict was correct.

## Recommended action

Keep as-is (MEDIUM). Fix should at minimum render `approver` as a subtitle/badge and, when `decision === "modify"`, show `call` → `modified` argument diff. `message` can be omitted or shown collapsed since it duplicates the assistant message.
