# F01.2 — ToolChoiceView renders literal `` `$name()` ``

**New verdict:** CONFIRMED

## What the finding claims

`ModelEventView.tsx:312` writes ``return <code>`${toolChoice.name}()`</code>;`` — JSX text is not a template literal, so the parser sees text `` `$ `` + expression `{toolChoice.name}` + text `` ()` ``. For `tool_choice: {name: "bash"}` the user sees `` `$bash()` `` instead of `bash()`.

## What the repro's bug_description says to look for

> **Where:** Transcript tab → expand **Model Call: mockllm/model** → click the **Tools** tab → look at the **Tool Choice** row
> **Observed:** Tool Choice shows the literal text `` `$my_forced_tool()` `` (backtick, dollar sign, name, parens, backtick).
> **Expected:** Tool Choice should show `my_forced_tool()` with no stray `` ` `` or `$`.

## Analysis

Screenshot, DOM `outerHTML`, and `inner_text` all agree: the Tool Choice cell renders the literal string `` `$my_forced_tool()` ``. This matches the finding's prediction character-for-character and matches the repro's `observed` text exactly.

Source re-read confirms the cause — `src/inspect_ai/_view/ts-mono/packages/inspect-components/src/transcript/ModelEventView.tsx:312` is still:
```tsx
return <code>`${toolChoice.name}()`</code>;
```
JSX children are parsed as JSXText / JSXExpressionContainer, not as a template literal; the backticks and `$` are plain text nodes.

A reasonable user would consider this a bug: the forced-tool indicator is polluted with stray `` ` `` and `$` characters that look like a syntax error. Reachability is gated only by F04.2's `tools.length > 1` (the regenerated repro works around that with two `ToolInfo`s and a synthetic `ModelEvent`). Prior CONFIRMED verdict stands.

## Recommended action

Keep as-is (HIGH). Fix: `return <code>{toolChoice.name}()</code>;` (or ``return <code>{`${toolChoice.name}()`}</code>;``).
