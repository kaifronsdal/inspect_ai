# F21.2 — Categorical filter autocomplete shows `undefined`

**Prior verdict:** CONFIRMED
**New verdict:** CONFIRMED
**Batch:** 20-samples | **Port:** 7640 | **Log:** `2026-04-24T01-29-57-00-00_F21.2-categorical-filter-undefined_AxGDVaRm9UazeBDCFsEFJV.eval`

## What the finding claims

`categoricalScoreDescriptor` (`CategoricalScoreDescriptor.tsx:10`) populates `categories` with raw string values, but the consumer in `filters.ts:182-185` reads `(cat as Record<string,unknown>).val`, which is `undefined` for bare strings. Result: filter autocomplete and the scorer tooltip show `undefined` instead of the actual category values.

## What the repro's bug_description says to look for

> **observed:** Autocomplete suggests `== "undefined"`, `== "undefined"`, `== "undefined"` — one per category. The tooltip reads `categories: undefined undefined undefined`. The actual category values (`good`, `bad`, `ugly`) are nowhere to be seen.
> **expected:** Autocomplete should suggest `== "good"`, `== "bad"`, `== "ugly"`.

## Analysis

**Verdict matches prior CONFIRMED.** Both halves of the claim reproduce:

1. **Autocomplete RHS values** — `undefined` is offered instead of `"good"` / `"bad"` / `"ugly"`. (Minor nit on the repro's `observed` text: it predicts three quoted `"undefined"` entries; in practice CodeMirror dedups to a single unquoted `undefined` because `valueToString(undefined)` → `String(undefined)` → `undefined`, not `"undefined"`. The bug is the same.)
2. **Tooltip** — `categories: undefined undefined undefined` (one per category) matches the finding verbatim.

Source confirms: `CategoricalScoreDescriptor.tsx:10` returns `categories: values` (raw `ScoreValue[]` strings); `filters.ts:182-184` does `const val = (cat as Record<string, unknown>).val; return valueToString(val);` — `.val` on a string primitive is `undefined`. Contrast `PassFailScoreDescriptor` and `ObjectScoreDescriptor`, which return `{val, text}` objects.

A reasonable user would consider this a bug: the autocomplete is the primary discoverability mechanism for valid filter RHS values, and it is useless for any string-valued categorical scorer that isn't C/I/P/N. MEDIUM severity is appropriate.

## Recommended action

Keep as-is (CONFIRMED, MEDIUM). Optionally tighten the repro's `observed` wording to "a single `undefined` entry" rather than three quoted ones.
