# F04.8 — Zero-valued token counts render as blank

**Prior verdict:** CONFIRMED
**New verdict:** CONFIRMED
**Batch:** 01-events | **Port:** 7614 | **Log:** `2026-04-24T01-27-42-00-00_F04.8-usage-zero-renders-blank_BWhdC2nE85ZgE8vPrYfJTk.eval`

## What the finding claims

`ModelUsagePanel.tsx:124-126` renders `{row.value ? formatNumber(row.value) : ""}`, so a legitimate `0` (e.g. `input_tokens: 0` on a fully-cached request) shows as an empty cell instead of `0`.

## What the repro's bug_description says to look for

> **Observed:** input row: blank. cache_write row: blank. Reasoning row: blank. (But Output shows `50`, cache_read shows `100`, Total shows `150`.)
> **Expected:** Each row with a value of `0` should display `0`, not an empty cell.

## Analysis

The finding is correct as written. Source at `ModelUsagePanel.tsx:125` is exactly `{row.value ? formatNumber(row.value) : ""}`; with `row.value === 0` the ternary takes the `""` branch and the value `<div>` is empty. The screenshot and cell-by-cell DOM dump both show the INPUT row's value cell as empty while sibling rows render numbers.

A reasonable user looking at this panel would interpret the blank as "input tokens not reported" rather than "input tokens were zero" — meaningful data is hidden. The separator row at line 88-91 deliberately uses `value: undefined` to get a blank cell, so the ternary's intent was clearly to handle `undefined`/`null`, not `0`.

**Minor inaccuracy in the repro's `observed` text** (does not affect the verdict): it says `cache_write` and `Reasoning` rows render blank. In fact those rows are **absent entirely** — they're guarded by separate truthy checks at lines 42 (`if (usage.reasoning_tokens)`) and 72 (`if (usage.input_tokens_cache_write)`), so a `0` there suppresses the whole row, not just the value. That is arguably a related bug but is *not* what F04.8 (line 124-126) describes. The `input` row alone is sufficient to confirm F04.8, since `input` is pushed unconditionally (line 58-62) and reaches the `row.value ?` check.

Prior verdict stands.

## Recommended action

Keep as-is (MEDIUM). Suggested fix in the finding (`row.value != null ? formatNumber(row.value) : ""`) is correct. Optionally tighten the repro's `observed` text to drop the `cache_write`/`Reasoning` claims, or note they are omitted entirely rather than blank.
