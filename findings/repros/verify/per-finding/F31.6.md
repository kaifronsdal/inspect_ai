# F31.6 — `evalSampleCount` collapses to 0 when `epochs` is unset

**Prior verdict:** FALSE_POSITIVE
**New verdict:** FALSE_POSITIVE
**Batch:** 30-loglist | **Port:** 7648 | **Log:** `2026-04-24T01-25-09-00-00_F31.6-sample-count-epochs-zero_STkdSTCKeyVTyqnFVfmM8X.eval`

## What the finding claims

`SamplesTab.tsx:89-92` computes `evalSampleCount = (limitCount || dataset.samples || 0) * (config.epochs || 0)`; since `EvalConfig.epochs` is optional, a single-epoch eval that omits `epochs=` will have `null` here → product is `0` → `SampleList` receives `totalItemCount={0}` and the footer shows "of 0".

## What the repro's bug_description says to look for

> **observed:** "Expected-total is computed as `3 * (config.epochs || 0) = 0`. Wherever `totalItemCount` surfaces (e.g. 'N of M' progress, footer count), M is `0` despite there being 3 samples. Confirm in JSON tab that `eval.config.epochs` is `null`."
> **expected:** "Default to `1`, not `0`: total should be `3`."

## Analysis

The finding's load-bearing premise — that omitting `epochs=` in a `Task` yields `config.epochs == null` in the log — is **false**. `eval_config_defaults()` (`src/inspect_ai/log/_log.py:73-84`) returns `{"epochs": 1, …}`, and `_eval/task/log.py:174-176` applies those defaults to `eval_config` before the log is written. Consequently every real `.eval` has `config.epochs >= 1`, and `(config.epochs || 0)` at `SamplesTab.tsx:91` always evaluates to ≥1. The repro task itself proves this: it deliberately omits `epochs=`, yet the resulting log has `"epochs": 1`.

The repro's instruction "Confirm in JSON tab that `eval.config.epochs` is `null`" fails its own check — it is `1`.

Adversarial note on the footer evidence: `SampleFooter.tsx:35-37` renders `sampleCount < totalSampleCount ? "N / M Samples" : "N Samples"`. With `sampleCount=3`, both `totalSampleCount=3` and `totalSampleCount=0` produce `"3 Samples"` (since `3 < 0` is false), so the footer text *alone* would not distinguish a fired-but-masked bug from correct behaviour. The decisive evidence is the JSON: `epochs` is `1`, so `evalSampleCount = 3 * 1 = 3` and the `|| 0` branch is never taken. The previous verdict's reasoning (Python always defaults epochs to ≥1) is correct and confirmed.

The `|| 0` at `SamplesTab.tsx:91` remains a code smell (inconsistent with `|| 1` at `SampleList.tsx:78`) but is unreachable from any inspect-generated log.

## Recommended action

Remove finding (or downgrade to INFO/code-smell: "change `|| 0` → `|| 1` for defence-in-depth / consistency with `SampleList.tsx:78`"). No observable user-facing bug.
