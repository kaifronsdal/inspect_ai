# F90.3 — Transcript ScoreEvent bypasses the score-descriptor system

**Prior verdict:** CONFIRMED
**New verdict:** CONFIRMED
**Batch:** 90-cross | **Port:** 7654 | **Log:** `2026-04-23T04-58-06-00-00_F90.3-score-event-bypasses-descriptor_HHiyYHCi8yhwcmYNTuSncR.eval`

## What the finding claims

`packages/inspect-components/src/transcript/ScoreValue.tsx:18-26` renders score values via `String(value)` for scalars, while the sample header / list / Scoring tab render the same value via `apps/inspect/src/app/samples/descriptor/score/BooleanScoreDescriptor.tsx:14-26` (a green/red circled badge). Result: a fourth independent renderer for the same value, producing visually divergent output for booleans, `"C"`/`"I"`, and unrounded numerics.

## What the repro's bug_description says to look for

> **Observed:** Header / sample list / Scoring tab show a coloured circle badge for `true`. The ScoreEvent panel in the transcript shows plain unstyled text `true` for the same value.
> **Expected:** The transcript ScoreEvent should render the value through the same `ScoreDescriptor.render()` path as the header.

## What I actually observed

**Screenshot:** `artifacts/per-finding/F90.3-page.png` (also `F90.3-header.png`, `F90.3-panel.png`)

The full-page screenshot shows both renderings **in the same viewport**:
- Top-right header SCORE column: a solid **green oval badge** with white text `true`.
- Bottom of transcript, SCORE event panel, "Score" row: plain black body text `true` — no colour, no badge, no pill shape.

**DOM evidence:**
```
Header score cell:
  <div class="... _centerValue_1foh6_21">
    <span class="_circle_qymy9_1 text-size-small _green_qymy9_12">true</span>
  </div>

ScoreEvent panel "Score" row:
  <div class="text-style-label">Score</div>

```

Header badge classes map to `BooleanScoreDescriptor.module.css` (`.circle` → 40×30px rounded pill; `.green` → `background-color: var(--bs-success)`). The transcript value is a bare `<div class="">` — no styling whatsoever.

## Analysis

Source code reads exactly as the finding says:

- `ScoreValue.tsx:24` → `return String(value);` for all non-array/non-object values.
- `BooleanScoreDescriptor.tsx:14-26` → `<span className={clsx(styles.circle, ..., score ? styles.green : styles.red)}>{String(score)}</span>`.

The architectural cause is that `ScoreValue` lives in `packages/inspect-components` (shared) while descriptors live in `apps/inspect` (app-level), so the transcript renderer can't reach the descriptor without it being threaded through. This explains *why* it happened but is not a design intent — there's no comment or rationale suggesting the divergence is deliberate; it's the consistency drift the finding describes.

The boolean case is cosmetic on its own (the text `true` is correct, just unstyled), but the same `String(value)` fallback also produces unrounded `0.6666666666` numerics and unbadged `"I"` pass-fail, and it sits in the same viewport as the badge — so a user comparing the two is reasonably confused. The MEDIUM severity is carried by the systemic "fourth independent renderer" claim, which the source confirms.

Prior verdict was correct.

## Recommended action

Keep as-is (CONFIRMED, MEDIUM). Roll into the unified-score-rendering fix alongside F20.4 / F21.10 / F90.14.
