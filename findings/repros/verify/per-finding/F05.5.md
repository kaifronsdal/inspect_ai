# F05.5 — ScoreEditEventView hides edited value when it is `0`/`False`/`""`

**Prior verdict:** CONFIRMED
**New verdict:** CONFIRMED
**Batch:** 01-events | **Port:** 7617 | **Log:** `2026-04-24T01-27-51-00-00_F05.5-score-edit-falsy-value-hidden_KuRWtNxiqgp7PyDqASkmgd.eval`

## What the finding claims

`ScoreEditEventView.tsx:50-58` guards the Value row with `{event.edit.value ? <Fragment>…<ScoreValue …/></Fragment> : ""}`. Since `Score.value` is `string | number | boolean | …`, the legitimate edited values `0`, `false`, and `""` fail the truthy check and the **Value** row is silently dropped from the "Updated Values" grid.

## What the repro's bug_description says to look for

> **Where:** Transcript tab → expand each of the three **Score Edit** events
> **Observed:** No Value row in any of the three panels — only the Explanation is shown. The user cannot see what the score was changed TO.
> **Expected:** Each panel should show **Value: 0** / **Value: False** / **Value: (empty)** respectively.

## What I actually observed

**Screenshots:** `artifacts/per-finding/F05.5-page.png`, `F05.5-panel-0.png`, `F05.5-panel-1.png`, `F05.5-panel-2.png`

Each of the three "Edit Score" panels renders an **UPDATED VALUES** section containing only two rows — **ANSWER** (`[unchanged]`) and **EXPLANATION**. There is no **VALUE** row in any panel. The panel for `value=0` reads, under its own UPDATED VALUES heading: `ANSWER [unchanged]` / `EXPLANATION Edited value to 0 (int)…` — and nothing else. Identical layout for `value=False` and `value=""`.

**DOM evidence (panel 0 grid container, `value=0`):**

inner_text rows for all 3 panels: `VALUE label present = False`; `ANSWER present = True`; `EXPLANATION present = True`.

## Analysis

The behaviour matches the finding exactly and the source code confirms the root cause: `ScoreEditEventView.tsx:50` uses a bare truthiness test on `event.edit.value`. The grid container's first child is the `Answer` separator — the `Value` label / `<ScoreValue>` fragment was never emitted into the DOM (not merely empty or CSS-hidden).

This is not cosmetic: the panel is titled "Edit Score" with a section header "Updated Values", yet the *one field that was actually updated* (the score value) is absent, while the un-edited Answer is shown as `[unchanged]`. Editing `1 → 0` or `True → False` are the canonical manual-grading corrections, so the falsy case is the common case, not an edge case. A reasonable user would have no way to determine what the score was changed to.

Prior verdict stands; nothing was overstated.

## Recommended action

Keep as-is (MEDIUM). Fix per the finding's suggestion: replace the guard with `event.edit.value !== undefined && event.edit.value !== kUnchangedSentinel` (which also resolves F01.3's inverse leak).
