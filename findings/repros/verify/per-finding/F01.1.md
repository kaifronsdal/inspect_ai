# F01.1 — ModelEventView Summary tab drops preceding messages when input ends with assistant

**Prior verdict:** CONFIRMED
**New verdict:** CONFIRMED
**Batch:** 01-events | **Port:** 7600 | **Log:** `2026-04-24T01-27-30-00-00_F01.1-model-summary-drops-preceding_DLod8CfmqU8yxUdgNBMrZ6.eval`

## What the finding claims

`ModelEventView.tsx:67-86` — when the last input message is an assistant message, `offset` is set to `-1` and the loop iterates `event.input.slice(offset)`. `Array.slice(-1)` returns **only the last element**, so the loop re-visits the assistant message, hits `else { break; }` immediately, and never collects the preceding user/system messages. Intended: `slice(0, offset)`.

## What the repro's bug_description says to look for

- **Observed:** "Summary shows only the trailing **assistant** message + the model output. The user message (containing the ⚠️ marker) and the system message are MISSING."
- **Expected:** "Summary should show `[system, user (⚠️ marker), assistant, output]` — all messages immediately preceding the trailing assistant message."

## What I actually observed

**Screenshot:** `artifacts/per-finding/F01.1-page.png` (full page, Summary tab active), `artifacts/per-finding/F01.1-panel.png` (Model Call panel, Summary tab), `artifacts/per-finding/F01.1-all-tab.png` (same panel, All tab)

The Summary tab of the "MODEL CALL: MOCKLLM/MODEL" event renders exactly **two** message cards, both labelled **ASSISTANT**: (1) the trailing compaction-style assistant message, (2) the model output. No SYSTEM card, no USER card, no ⚠️ sentinel text. The All tab on the same panel renders all five messages including `1 SYSTEM ⚠️ SYSTEM MESSAGE — IF YOU CANNOT SEE THIS…` and `3 USER ⚠️ USER MESSAGE — IF YOU CANNOT SEE THIS…`.

**DOM evidence (Summary tab `.tab-pane.active` inner_text):**
```
ASSISTANT

[trailing assistant / compaction-style message]

Because this assistant message is the LAST entry in event.input, the Summary tab
sets offset = -1 and then iterates event.input.slice(-1) — which is just this
message. The user and system messages above never get collected.

ASSISTANT

[model output] — end of summary.
```

Sentinel `"IF YOU CANNOT SEE THIS IN THE SUMMARY TAB"` — present in All tab: **True**; present in Summary tab: **False**.

## Analysis

Verdict matches prior. All three legs hold:

1. **Source confirms.** `ModelEventView.tsx:74` is `for (const msg of event.input.slice(offset).reverse())` with `offset = -1` set at L71. `[].slice(-1)` → one-element array → reversed loop visits the assistant, fails the `user|system|tool` test (L76-80), `break`s (L84). The `offset` variable only makes sense as a second arg to `slice`; passing it as the *first* arg is the bug. The comment at L53-55 ("For any user messages which immediately preceded this model call … display those user messages") states the opposite intent, ruling out BY_DESIGN.
2. **Repro reaches the path.** `event.input = [system, user, user, assistant]` so `lastMessage.role === "assistant"` is true and `agentResultsFiltered` is false.
3. **Rendered output is wrong** in a way a reasonable user would notice: the Summary tab — the default view of a model call — shows assistant→assistant with zero prompt context, while the All tab proves the system/user messages are in `event.input`. Anyone reviewing a compaction-style turn from Summary alone would not see what was actually sent to the model.

Minor mitigation that does **not** change the verdict: a "Show all messages" link exists (L119-136) but is gated on `context?.inlineExpansionUX`, which is unset in the standard inspect viewer — no such link is rendered (confirmed absent in screenshot/DOM).

## Recommended action

Keep as-is (HIGH). Fix is the one-liner the finding proposes: `event.input.slice(0, offset).reverse()`.
