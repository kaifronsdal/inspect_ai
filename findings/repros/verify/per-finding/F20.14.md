# F20.14 — List/Object score descriptors mis-format `0` and `false`

**Prior verdict:** CONFIRMED
**New verdict:** CONFIRMED
**Batch:** 20-samples | **Port:** 7638 | **Log:** `2026-04-24T01-29-55-00-00_F20.14-list-score-zero-unformatted_HhEL5c6TjRia5xyrJmNC5j.eval`

## What the finding claims

`ListScoreDescriptor.tsx:27-33` / `ObjectScoreDescriptor.tsx:51-57` use `value && isNumeric(value) ? formatPrettyDecimal(...) : String(value)`. The `&&` short-circuits on falsy `0` / `false`, so `0` renders as `"0"` (bare `String()`) while sibling values `0.333333` → `"0.333"` and `1` → `"1.0"` go through `formatPrettyDecimal`, producing visually inconsistent list/dict-score cells.

## What the repro's bug_description says to look for

> **Observed:** List score `[0, 0.333333, 1]` renders as `[0, 0.333, 1.0]` — the first element `0` is bare (`String(0)`) while `1` is formatted as `1.0` (`formatPrettyDecimal`).
> **Expected:** `0` should be formatted via the same `formatPrettyDecimal` path as every other numeric element, i.e. shown as `0.0`.

## Analysis

The rendered output matches the finding and the repro's `observed` claim exactly. Source-code reading confirms the mechanism:

- `ListScoreDescriptor.tsx:27`: `value && isNumeric(value) ? formatPrettyDecimal(...) : String(value)` — `0` is falsy → `String(0)` → `"0"`.
- `format.ts:72-73`: `formatPrettyDecimal(n)` returns `n.toFixed(1)` for integers, so `formatPrettyDecimal(0)` *would* return `"0.0"` and `formatPrettyDecimal(1)` returns `"1.0"`.

Hence `1` reaches the formatter and becomes `1.0`, while `0` is diverted to `String()` and stays `0`. The same guard exists verbatim in `ObjectScoreDescriptor.tsx:51`. The dict-scorer column is not shown in the grid by default (only one score column is selected via the SCORERS picker), but the list column alone demonstrates the inconsistency unambiguously.

The prior CONFIRMED verdict is correct. Impact is purely cosmetic — no data is lost or misrepresented, just inconsistent decimal-place formatting within a single cell. The finding's existing LOW severity is appropriate.

## Recommended action

Keep as-is (LOW). Fix is trivial: change the guard to `isNumeric(value) ? formatPrettyDecimal(typeof value === "number" ? value : parseFloat(String(value))) : String(value)` (drop the `value &&`), in both `ListScoreDescriptor.tsx` and `ObjectScoreDescriptor.tsx`.
