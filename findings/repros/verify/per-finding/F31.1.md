# F31.1 — `EvalConfig` is built but never rendered in Task tab

**Prior verdict:** CONFIRMED (VERIFICATION.md) / PARTIAL — severity overstated (91-high-severity-verification.md)
**New verdict:** CONFIRMED (recommend MEDIUM severity)
**Batch:** 30-loglist | **Port:** 7645 | **Log:** `2026-04-24T01-25-03-00-00_F31.1-eval-config-not-rendered_42jtxtXmJ7DVYNEn4wGapn.eval`

## What the finding claims

`TaskTab.tsx:54-59` copies every key of `evalSpec.config` into a local `config` record and never references it again, so `EvalConfig` (epochs, message_limit, token_limit, fail_on_error, etc.) is unreachable from the structured UI.
`src/inspect_ai/_view/ts-mono/apps/inspect/src/app/log-view/tabs/TaskTab.tsx:54-59`

## What the repro's bug_description says to look for

> **observed:** None of `epochs=7`, `message_limit=42`, `token_limit=999999`, `fail_on_error=0.5` appear anywhere in the Task tab.
> **expected:** A **Config** card listing the `EvalConfig` fields. Open the JSON tab and search for `"epochs": 7` to confirm the data is present in the log.

## Analysis

Source confirms the dead code: `TaskTab.tsx:54-59` builds `config` and the JSX at lines 114-178 renders only `taskInformation`, `earlyStopping`, and `task_args` — `config` is never read. The screenshot and DOM extraction confirm none of the four sentinel `EvalConfig` values (`epochs=7`, `message_limit=42`, `token_limit=999999`, `fail_on_error=0.5`) appear in the Task, Info, or Models tabs, nor in the navbar SecondaryBar.

Adversarial checks:
- The single `"42"` substring hit in the Task tab is the Task ID `42jtxtXmJ7DVYNEn4wGapn`, **not** `message_limit=42` — false alarm.
- The SecondaryBar's "Config" column (`SecondaryBar.tsx:94-107`) renders `{...evalPlan?.config, ...evalSpec.task_args}` — that is `GenerateConfig` + task args, **not** `EvalConfig`. Even when present it would not show `message_limit`/`token_limit`/`fail_on_error`. In this repro both sources are empty so the column doesn't render at all.
- `epochs=7` does leak into the SecondaryBar **implicitly** as the dataset multiplier ("1 x 7 samples", via `SecondaryBar.tsx:49` → `formatDataset`), but it is not labelled as a config field and the other limits remain completely invisible.
- Info tab (PlanCard) shows Dataset / Solvers / Scorer only — no EvalConfig.

The bug is real and exactly as described. I agree with 91-verification that HIGH is generous: this is a missing-display / dead-code regression (data still reachable via JSON tab), consistent with MEDIUM ratings elsewhere for "field not surfaced" findings.

## Recommended action

Keep finding; **downgrade severity to MEDIUM**. Fix by adding a `<Card><CardHeader label="Config"/><MetaDataGrid entries={config}/></Card>` block in `TaskTab.tsx` when `Object.keys(config).length > 0`, or delete the dead loop if the omission is intentional.
