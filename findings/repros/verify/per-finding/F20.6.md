`SampleSummaryView.tsx:76,185-191` reads only `sample.limit?.type`; the numeric `.limit` value "is not surfaced anywhere outside the raw JSON tab."

> **Expected:** At least one of the limit displays should read `token (12345)` or similar.

## Analysis

The finding's load-bearing claim — *"not surfaced anywhere outside the raw JSON tab"* — is factually wrong. `SampleLimitEventView.tsx:71` renders `eventNode.event.message`, and Python builds that message as `f"Token limit exceeded. value: {total:,}; limit: {self.limit:,}"` (`src/inspect_ai/util/_limit.py:602`). The threshold is therefore shown in the transcript, formatted with a thousands separator. The repro's "Ctrl-F for `12345`" instruction is what makes it look absent — the rendered text is `12,345`, not `12345`.

The **narrower** claim — that `SampleSummaryView.tsx:76` reads only `.type` — is true at source level (`const limit = … sample.limit?.type`), but it is **unobservable** in this repro: the header renders no Limit column at all because `limitSize` is `0` (the F20.1 bug masks it). Even if it did render, "Limit: token" in a 3-em header cell with the full `value: 20,000; limit: 12,345` one click below in the transcript is not a user-visible bug.

Prior FALSE_POSITIVE verdict is correct.

## Recommended action

Remove finding (or fold the narrow `SampleSummaryView` `.type`-only observation into F20.1's fix as a one-line "also show `.limit`" note). Drop the "nowhere outside JSON" claim — it is wrong.
