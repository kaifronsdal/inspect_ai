# F90.7 — `kModelNone` ("none/none") suppressed in title bar but leaks elsewhere

**Prior verdict:** CONFIRMED
**New verdict:** CONFIRMED
**Batch:** 90-cross | **Port:** 7657 | **Log:** `2026-04-23T04-58-35-00-00_F90.7-kmodelnone-leaks_nRRzMRHyGLSxx8pRwnmWzk.eval`

## What the finding claims

`PrimaryBar.tsx:74` guards `evalSpec.model !== kModelNone` before rendering the model name, but `log-list/grid/columns/hooks.tsx:160-161`, `samples-panel/SamplesPanel.tsx:182`, and `plan/ModelCard.tsx:24,57` render the raw string with no guard — so an eval with `model="none"` shows blank in the title bar but literal `none/none` in the log list, samples grid, and Models tab.

## What the repro's bug_description says to look for

> **Observed:** Title bar treats `none/none` as a sentinel and hides it. Log-list Model column, multi-log Samples-grid Model column, and the Models-tab card all leak the raw string `none/none`.
> **Expected:** All four surfaces should suppress / replace the sentinel (e.g. show `—` or the first model_role instead).

## Analysis

Reproduces exactly as the finding describes, and source inspection confirms the asymmetry:

- `PrimaryBar.tsx:74`: `{evalSpec?.model && evalSpec.model !== kModelNone ? <div id="task-model">…</div> : ""}` — guard present; DOM shows `#task-model` count = 0.
- `hooks.tsx:160-161`: `if (item.model) { return <div className={styles.modelCell}>{item.model}</div>; }` — no guard; renders `none/none`.
- `ModelCard.tsx:24,57`: builds `modelsInfo.eval = { model: evalSpec.model, … }` and renders `<div>{modelInfo.model}</div>` — no guard; renders `none/none`.
- `SamplesPanel.tsx:182`: `model: logDetail.eval.model || ""` — no guard (not screenshot-verified here since the multi-log Samples grid needs ≥2 logs aggregated, but the source is unambiguous).

**Is showing `none/none` actually wrong?** It is the literal value of `eval.model`, so it is not *false* — but it is an internal sentinel (`constants.ts: kModelNone = "none/none"`), not a real provider/model pair. The codebase itself acknowledges this by special-casing it in `PrimaryBar`. A user scanning the log list sees what looks like a provider called `none` with a model called `none`, which is implementation-detail leakage. The *inconsistency* — one surface treating it as a sentinel while three adjacent surfaces treat it as data — is the bug, and that inconsistency is plainly visible in `F90.7-page.png` (header omits it, ModelCard 2 inches below prints it).

The prior CONFIRMED verdict was correct. The finding's note that the title bar shows "blank" is slightly imprecise — it actually falls through to showing the model_role (`WORKER:mockllm/model`) — but the core claim (sentinel suppressed there, leaked elsewhere) holds.

## Recommended action

Keep as-is. LOW severity is appropriate: cosmetic, only affects the uncommon `model="none"` + `model_roles` workflow, and is non-blocking. Fix is trivial (apply the same `!== kModelNone` guard in the three other locations, or render `—` / omit the `eval` row in ModelCard when the model is the sentinel).
