# F30.2 — Status icons differ between log-list grid and log-detail header

**Prior verdict:** CONFIRMED
**New verdict:** CONFIRMED
**Batch:** 30-loglist | **Port:** 7643 | **Log:** `2026-04-24T01-25-11-00-00_F30.2-status-icon-mismatch-ERROR_8g7hPArS4dMqkzL22LfZUa.eval`

## What the finding claims

`apps/inspect/src/app/log-list/grid/columns/hooks.tsx:218-244` and `apps/inspect/src/app/log-view/title-view/StatusPanel.tsx:12-29` map the same `EvalStatus` to different Bootstrap icons. Specifically: for `error`, the grid uses `ApplicationIcons.error` (`bi-exclamation-circle-fill`) while the title-bar uses `ApplicationIcons.logging.error` (`bi-x-circle`); for `cancelled`, the grid uses `bi-x-circle` while the title-bar uses `bi-info-square`. The collision: `bi-x-circle` means "cancelled" in the list but "error" one click deeper.

## What the repro's bug_description says to look for

> **Observed:** "List shows `bi-exclamation-circle-fill` for `error`; detail header shows `bi-x-circle` for the same `error` status. (`bi-x-circle` is what the *list* uses for `cancelled` — so the same glyph means two different things one click apart.)"
> **Expected:** "Same icon in both places. The list's mapping (`ApplicationIcons.error` / `ApplicationIcons.cancelled`) is the correct one; `StatusPanel.tsx` should match it."

## Analysis

**Source confirms the finding exactly.** `icons.ts` defines `ApplicationIcons.error = "bi bi-exclamation-circle-fill"` (line 70) and `ApplicationIcons.cancelled = "bi bi-x-circle"` (line 36), while `loggingIcons.error = "bi bi-x-circle"` (line 7) and `loggingIcons.info = "bi bi-info-square"` (line 5). `hooks.tsx` uses the former pair; `StatusPanel.tsx` uses the latter pair. So:

| status | grid glyph | header glyph |
|---|---|---|
| `error` | `bi-exclamation-circle-fill` | `bi-x-circle` |
| `cancelled` | `bi-x-circle` | `bi-info-square` |

**Are they conflicting or just different-but-clear?** They are genuinely **conflicting**, not merely different: the `bi-x-circle` glyph carries two contradictory meanings depending on which screen you're on (cancelled in the grid, error in the header). A user who has internalised "⊗ = cancelled" from the list will misread the header at a glance. The header's adjacent "Task Failed" text label mitigates real-world confusion, but the iconography is still self-inconsistent — and the `cancelled → bi-info-square` header mapping is semantically wrong on its own (info icon for a cancellation).

The prior CONFIRMED verdict stands; no overstatement found.

## Recommended action

Keep as-is (MEDIUM). Fix is the one-liner the finding suggests: change `StatusPanel.tsx` to use `ApplicationIcons.error` / `ApplicationIcons.cancelled` instead of `ApplicationIcons.logging[...]`.
