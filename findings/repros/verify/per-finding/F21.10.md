# F21.10 — Multi-log SamplesGrid vs single-log SampleList format the same score differently

**Prior verdict:** CONFIRMED
**New verdict:** CONFIRMED
**Batch:** 20-samples | **Port:** 7641 | **Log:** `2026-04-24T01-29-59-00-00_F21.10-multilog-a_VpHv8x9HbpYzJQbJ86aTgc.eval` (+ `…multilog-b…`)

## What the finding claims

The multi-log `SamplesGrid` (`apps/inspect/src/app/samples-panel/samples-grid/hooks.tsx:183-219`) hard-codes its own score formatters (`value.toFixed(3)`, `JSON.stringify`, `String(value)`) instead of reusing the score descriptors that the single-log `SampleList` (`apps/inspect/src/app/samples/list/columns.tsx:288-314`) uses, so the same sample's scores render differently in the two grids.

## What the repro's bug_description says to look for

> • `passfail` score `C`: single-log list → **green circle badge**; multi-log grid → plain string `C`.
> • `numeric` score `1.0`: single-log list → `1` (`formatDecimalNoTrailingZeroes`); multi-log grid → `1.000` (`value.toFixed(3)`).
> • `dict` score: single-log → key/value grid; multi-log → raw `{"a":1,"b":0}` JSON blob.

## Analysis

All three claimed divergences reproduce side-by-side, on screen and in the DOM, for the exact same sample:

| Score | Multi-log grid | Single-log list |
|---|---|---|
| passfail `"C"` | plain `C` (no `circle` class) | `<span class="_circle_… _green_…">C</span>` badge |
| numeric `2.0` | `2.000` | `2` |
| dict `{a:1,b:0}` | `{"a":1,"b":0}` | columns `A`=`1`, `B`=`0` |

The source matches the behaviour exactly: `hooks.tsx:198-210` does `typeof value === "object" → JSON.stringify(value)`, `typeof value === "number" → value.toFixed(3)`, else `String(value)`; whereas `columns.tsx:304-306` calls `samplesDescriptor.evalDescriptor.score(...)?.render()`, which dispatches to `PassFailScoreDescriptor.tsx:46` (circle badge), `NumericScoreDescriptor.tsx:31` (`formatDecimalNoTrailingZeroes`), and the object descriptor (per-key columns). The finding's reading of the code is accurate; nothing in source suggests the grid divergence is intentional.

The prior CONFIRMED verdict was correct. This pass adds the missing direct comparison of `numeric` and `dict` rendering in the single-log list (the prior check only inspected `score-0`/passfail on the list side and inferred the rest).

This is a real, user-visible inconsistency: a user toggling between the cross-log Samples panel and a per-log Samples tab sees `C` vs a green badge, `2.000` vs `2`, and a JSON blob vs split columns for the same row. MEDIUM severity is appropriate.

## Recommended action

Keep as-is (CONFIRMED, MEDIUM). Fix per the finding's suggestion: have `useSampleColumns` reuse `getScoreDescriptorForValues` for `valueFormatter`/`cellRenderer` instead of the inline `toFixed`/`JSON.stringify` block.
