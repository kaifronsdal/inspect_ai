# F05.6 — ScoreEditEventView Metadata nested inside Summary → never becomes a tab

**Prior verdict:** CONFIRMED
**New verdict:** CONFIRMED_MINOR
**Batch:** 01-events | **Port:** 7618 | **Log:** `2026-04-24T01-27-53-00-00_F05.6-score-edit-metadata-not-tab_gKGEYXUdEU7ib8AzScE7Sj.eval`

## What the finding claims

`ScoreEditEventView.tsx:39,118-127` — the `<div data-name="Metadata">` is a child of `<div data-name="Summary">`, not a direct child of `EventPanel`. Since `EventPanel.tsx:92-98,199-212` discovers tabs by reading `data-name` only on **direct** children, the Metadata block never becomes a tab; it renders inline at the bottom of Summary instead. Contrast `ScoreEventView.tsx:67-76` where Metadata is a sibling and correctly produces a second tab.

## What the repro's bug_description says to look for

- **Observed:** "Score Edit panel has **only one tab (Summary)**. The metadata grid (`edited_by`, `edit_reason`, …, `MARKER`) is rendered **inline at the bottom of Summary** with a dead `data-name` attr."
- **Expected:** "A separate **Metadata** tab alongside Summary — exactly like `ScoreEventView` does (see the **Score** event in this same transcript, which DOES have a Metadata tab)."

## Analysis

The finding reproduces exactly as described, and the source code matches:

- `ScoreEditEventView.tsx:39` opens `<div data-name="Summary">`; lines 118-127 place `<div data-name="Metadata">` *inside* that div; line 128 closes Summary. So `EventPanel` receives exactly one direct child.
- `EventPanel.tsx:92-94` flattens only direct `children`; line 199 gates the `EventNavs` pill strip on `filteredArrChildren.length > 1`. With one child, no nav is rendered → DOM shows `<div class="_navs_...></div>` empty.
- `ScoreEventView.tsx:40,67-76` puts Metadata as a **sibling** of `<div data-name="Explanation">` → two direct children → two pills (`EXPLANATION | METADATA`), confirmed in screenshot.

**Is the metadata still VISIBLE, or actually hidden?** It is **still visible** — every key/value renders inline. No data loss. The user-facing effects are: (a) inconsistency with ScoreEvent, (b) no "Metadata" section label so the block looks like it belongs to Provenance, and (c) a dead `data-name="Metadata"` attribute. This is cosmetic/consistency, not a correctness bug.

The prior CONFIRMED verdict was accurate. I'm marking it CONFIRMED_MINOR only because the task asked specifically whether metadata is hidden — it is not, so impact is purely cosmetic and LOW severity is appropriate.

## Recommended action

Keep as-is at **LOW** severity. Trivial fix: in `ScoreEditEventView.tsx`, move the `event.edit.metadata` block (lines 118-127) outside the `<div data-name="Summary">` closing tag so it becomes a sibling, matching `ScoreEventView`.
