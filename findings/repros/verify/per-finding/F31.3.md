## Analysis

**Source confirms.** `PlanDetailView.tsx:26` is `const steps = plan?.steps;` and line 41 is `title: "Solvers"` (hard-coded). `rg "plan\.name|plan\?\.name" apps/inspect/src/` returns **zero hits** — no component anywhere in the inspect viewer reads `plan.name`.

**Screenshot + DOM confirm.** The sentinel is absent from every rendered tab except JSON. The Solvers column heading is the literal `"Solvers"`. This matches the repro's `observed` exactly.

**`plan.finish` half remains FALSE_POSITIVE** — the screenshot shows `f31_3_finish_solver` IS in the chain diagram, exactly as the prior re-audit said (`_eval/task/log.py:361-362` appends it to `steps`). The rebuilt repro correctly documents this in its `extra` field and no longer asserts on it.

**Impact caveat (why this stays LOW, not MEDIUM):** `Plan` is deprecated (`solver/_plan.py:67` — "Plan is deprecated: use chain()"); the repro had to pass `internal=True` to suppress the warning. `EvalPlan.name` defaults to `"plan"` (`log/_log.py:605`), so for the overwhelming majority of logs the value is uninformative anyway. A reasonable user setting a custom plan name *would* expect to see it somewhere, but very few users do this on a deprecated API.

**Agreement with prior verdict:** Yes — the rebuilt, plan.name-only repro reproduces cleanly. No change to verdict or severity.

## Recommended action

**Keep as-is** (LOW severity, scoped to `plan.name` only). Amend the finding text to drop the `plan.finish` clause and the "silently omitted from solver chain" sentence, and replace the suggested fix with: *"Show `plan.name` as the Solvers-column heading when it differs from the default `'plan'`."*
