# F03.5 — Outline → transcript navigation silently fails when target is collapsed

**Prior verdict:** CONFIRMED
**New verdict:** CONFIRMED
**Batch:** 02-transform | **Port:** 7610 | **Log:** `2026-04-24T18-32-04-00-00_F03.5-outline-nav-collapsed-target_PRzi7tGHAtXuh6xqrhheun.eval`

## What the finding claims

`TranscriptViewNodes.tsx:146-162` — `scrollToEvent` searches `flattenedNodes` (built from `collapsedTranscript` at line 115-117); if the outline-clicked target is hidden inside a collapsed transcript parent, `findIndex → -1` and the DOM-querySelector fallback also finds nothing → silent no-op. Outline collapse state and transcript collapse state are independent (`TranscriptLayout.tsx:792-806`).

## What the repro's bug_description says to look for

> **observed:** "Nothing happens — the transcript stays collapsed at `level1`, does not scroll, gives no feedback. `TranscriptVirtualListComponent` resolves the new `?event=` URL against `flattenedNodes` (built honouring `collapsedTranscript`), `findIndex → -1`, so `initialEventIndex` stays `undefined`."
> **expected:** "Transcript auto-expands `level1`/`level2`/`level3` and scrolls to `level4_CLICK_ME_in_outline` (or at minimum scrolls to the nearest visible ancestor)."

## Analysis

The regenerated plain-span repro works correctly: 4 nested `span(name)` levels render as a true collapsible tree (initial panel count = 30; after collapsing level1 → 2). The outline shows all 4 levels independently. Clicking the outline `<a>` for level4 fires the router (`?event=<uuid>` appears in the URL) but the transcript neither expands nor scrolls — `scrollTop` stays 0 and `level4` never enters the DOM.

Source confirms the mechanism: `flattenedNodes = flatTree(eventNodes, collapsedTranscript || defaultCollapsedIds)` (TranscriptViewNodes.tsx:115-117), so when level1 is in `collapsedTranscript` its descendants are absent from `flattenedNodes`; `findIndex` at :148 returns -1; the DOM fallback at :158 queries for an element that isn't rendered. No ancestor-expansion path exists.

The repro's `bug_description.observed` is **accurate** — it correctly describes the user-visible behaviour ("nothing happens, stays collapsed, no scroll, no feedback") and the mechanism (findIndex against post-collapse flattenedNodes → -1). A reasonable user would consider this a bug: the outline visibly accepts the click and selects the row, but the transcript ignores it with zero feedback.

Prior CONFIRMED verdict stands; the regenerated repro is sound.

## Recommended action

Keep as-is (MEDIUM). Suggested fix per the finding: before resolving the target index, walk ancestors of `eventId` in `eventNodes` and clear them from `collapsedTranscript`, or fall back to scrolling to the nearest visible ancestor.
