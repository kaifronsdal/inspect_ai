# F90.5 — Sample "Error" tab omits `error.message`; log "Error" tab shows it

**Prior verdict:** CONFIRMED
**New verdict:** CONFIRMED
**Batch:** 90-cross | **Port:** 7656 | **Log:** `2026-04-23T04-58-31-00-00_F90.5-sample-error-tab-drops-message_mLpueCLuHrvQSSHZ3QnQab.eval`

## What the finding claims

`apps/inspect/src/app/samples/SampleDisplay.tsx:607-623` renders the sample-level Error tab as `<CardHeader label="Sample Error"/><CardBody><ANSIDisplay output={sample.error.traceback_ansi}/></CardBody>` only, whereas `apps/inspect/src/app/log-view/error/TaskErrorPanel.tsx:29-44` renders the same `EvalError` as header-with-icon + `<ExpandablePanel><RenderedContent value={error.message}/></ExpandablePanel>` + ANSI traceback. The sample tab therefore has no dedicated `error.message` element.

## What the repro's bug_description says to look for

> **observed:** "The sample Error tab shows **only** the ANSI traceback … The distinctive `error.message` string appears only as the last line of the traceback … There is **no** dedicated message panel and **no** header icon. Contrast with the log-level Error tab which renders `error.message` in its own ExpandablePanel above the traceback."
> **expected:** "Sample Error tab should mirror `TaskErrorPanel`: header icon + `error.message` in an ExpandablePanel + ANSI traceback below it."

Sentinel: `F90.5_ERROR_MESSAGE_SHOULD_BE_VISIBLE`

## What I actually observed

**Screenshot:** `artifacts/per-finding/F90.5-page.png`, `artifacts/per-finding/F90.5-panel.png`

The Error tab shows a card titled **SAMPLE ERROR** (no icon). The card body contains exactly one element — the rich-formatted ANSI traceback (two boxed `Traceback (most recent call last)` blocks chained by "During handling of the above exception…"). At the very bottom, as the traceback's final line, is `RuntimeError: F90.5_ERROR_MESSAGE_SHOULD_BE_VISIBLE — this is `error.message`. It carries context (request_id=abc123, retries=5) …`. There is **no** separate message panel above the traceback.

**Answers to the verification questions:**
- Is the message sentinel visible **separately** from the traceback? → **No.** It appears only as the trailing `RuntimeError: …` line *inside* the ANSI traceback block.
- Is the message visible **at all**? → **Yes**, but only because Python's traceback formatter appends `<ExcType>: <message>` to `traceback_ansi`. It is not rendered from `error.message`.

**DOM evidence:**
```

CardBody direct children (exactly 1):
  <DIV> class='_ansiDisplayContainer_1749m_1 text-size-small _ansi_1si8b_29'

Sentinel in tab text:        True
Sentinel outside ANSI block: False
```

## Analysis

Source code matches the finding exactly:

- `SampleDisplay.tsx:609-621` — `<Card><CardHeader label="Sample Error"/><CardBody><ANSIDisplay output={sample.error.traceback_ansi} …/></CardBody></Card>`. No reference to `sample.error.message`; no header icon.
- `TaskErrorPanel.tsx:24-45` — `<CardHeader icon={ApplicationIcons.error} label="Task Failed"/><CardBody><ExpandablePanel …><RenderedContent entry={{…, value: error.message}}/></ExpandablePanel><ANSIDisplay output={error.traceback_ansi}/></CardBody>`.

DOM and screenshot confirm the rendered card body contains only the `_ansiDisplayContainer_*` div; stripping the ANSI block from the tab text leaves nothing but the header label. The sentinel only survives because it is embedded in `traceback_ansi`'s final line — i.e., the page is rendering `traceback_ansi`, not `error.message`.

The prior CONFIRMED verdict is correct. Caveat on impact: for ordinary Python exceptions the message is *not actually lost* on screen, since `traceback_ansi` already ends with `<Type>: <message>`. The finding's "data loss" framing applies only to the edge cases it names (empty traceback, or `error.message` carrying context not echoed in the traceback). The consistency bug — two cards for one `EvalError` shape, one with message+icon, one without — is real regardless.

## Recommended action

Keep finding; **downgrade severity to LOW**. The structural inconsistency vs `TaskErrorPanel` is real and the fix is trivial (reuse `TaskErrorCard` or add the `ExpandablePanel` + icon), but in the common case the message is still visible at the foot of the traceback, so user-facing data loss is rare.
