# F90.4 — Multi-log SamplesGrid "Status" column shows the LOG's status, not the sample's

**Prior verdict:** CONFIRMED
**New verdict:** CONFIRMED
**Batch:** 90-cross | **Port:** 7655 | **Log:** `2026-04-23T04-58-19-00-00_F90.4-multilog-grid-log-status-A_moJFN4HjL6xzwybSmdNnef.eval` (+ companion `…-B_…`)

## What the finding claims

`apps/inspect/src/app/samples-panel/SamplesPanel.tsx:183` builds each `SampleRow` with `status: logDetail.status` (the parent log's terminal status), and `samples-grid/hooks.tsx:151-159` renders that field as the per-row "Status" cell with no `cellRenderer`. So an errored sample in a successful eval shows Status = `success` in the multi-log grid, while the single-log Samples tab correctly derives per-sample status via `sampleStatus(completed, error)`.

## What the repro's bug_description says to look for

> **Observed:** In the multi-log Samples grid, sample `F90.4-errored` shows Status = **`success`** — because the column is filled from `logDetail.status` (the log finished successfully thanks to `fail_on_error=False`). Open the single-log Samples tab for log A and the same sample correctly shows a red error icon.
> **Expected:** Multi-log grid Status should be per-sample: `error` for `F90.4-errored`, `success` for `F90.4-ok`.

## What I actually observed

**Screenshot:** `artifacts/per-finding/F90.4-page.png` (grid), `F90.4-panel.png` (row), `F90.4-singlelog.png` (single-log comparison)

The `#/samples/` multi-log grid shows 11 rows. Row #7 has Sample ID `F90.4-errored` and its **Status** column reads **`success`** (plain text, no icon). The **Error** column (far right, mostly clipped off-viewport at default width — only "Ru…" visible) does carry the per-sample error string. Row #8 (`F90.4-ok`) also shows Status = `success`. Every row in the grid shows `success` — it's the parent log's status copied to every sample.

The single-log Samples tab for log A (screenshot `F90.4-singlelog.png`) correctly shows `F90.4-errored` with a **red error icon** and the RuntimeError text in its Status column, vs `F90.4-ok` with a green check + "ok".

## Analysis

**CONFIRMED.** Source, DOM, and screenshot all agree:

- Source at `SamplesPanel.tsx:183` literally reads `status: logDetail.status,` — the per-sample `sampleSummary.error` (line 190) and `sampleSummary.completed` (line 193) are captured on the same row object but never used to derive status.
- `hooks.tsx:151-159` defines the Status column with no `cellRenderer`/`valueFormatter`, so it renders the raw log-status string.
- The DOM Status cell for the errored sample contains exactly `success`.
- The Error column *does* contain the per-sample error (so the finding's "the per-sample error IS captured…" note is accurate), partially mitigating data loss — but it's the rightmost column, clipped off-screen at default viewport, and the Status column actively contradicts it.
- The single-log view of the same sample shows a red error icon, confirming the inconsistency the finding describes.

A reasonable user filtering/sorting the multi-log grid by Status to find failed samples would miss every errored sample in a `fail_on_error=False` eval. This is a genuine correctness/consistency bug at MEDIUM severity. Prior verdict was correct.

## Recommended action

Keep as-is (MEDIUM). Fix per the finding's suggestion: compute `status: sampleStatus(sampleSummary.completed, sampleSummary.error)` in `SamplesPanel.tsx` and add a `cellRenderer` reusing `SampleStatusIcon` in `samples-grid/hooks.tsx`.
